# 翼枢分流助手使用说明书

## 一、软件用途

翼枢分流助手用于将翼枢创建的全局 WireGuard 路由收窄为指定的内网资源路由。

启用分流后：

- 配置文件中的资源地址通过翼枢访问。
- 公网、本机网络和未列入配置的地址继续使用 Windows 原有路由。
- 后台服务持续检查翼枢、WireGuard 接口和目标路由。
- 翼枢暂时不可用时，服务等待其恢复；翼枢恢复后自动重新应用分流。

本软件只管理 Windows 路由和 WireGuard `AllowedIPs`，不设置 DNS，也不读取或修改 Windows hosts。

## 二、软件组成

软件由两个程序组成：

- **后台服务**：开机自动启动，负责检查翼枢和执行路由事务。
- **托盘程序**：用户登录后启动，负责显示状态以及接受启用、关闭等操作。

关闭托盘程序不会关闭分流。只有在托盘中选择“关闭分流”，或者停止后台服务，才会执行分流关闭和路由恢复。

## 三、运行要求

- Windows 10、Windows 11 或对应的 Windows Server x64 系统。
- 翼枢安装在 `C:\Program Files\YiShu`，或者在配置文件中填写实际路径。
- 翼枢能够正常登录和建立 `misas` 隧道。
- 发布和安装脚本使用 PowerShell 7 或更高版本运行。
- 安装、卸载和服务管理操作需要管理员权限。

正式发布物为自包含程序，安装后不要求目标计算机另行安装 .NET 运行时。

## 四、生成发布物

在开发目录 `D:\program\yishu-helper` 中打开 PowerShell 7，执行：

```powershell
cd D:\program\yishu-helper
.\scripts\发布.ps1
```

发布脚本会依次执行：

1. Release 构建。
2. 离线自检。
3. 生成 Windows x64 自包含后台服务。
4. 生成 Windows x64 自包含托盘程序。
5. 复制正式配置样例。

发布结果位于：

```text
D:\program\yishu-helper\artifacts
```

发布成功不等于已经安装；该操作不会注册服务，也不会修改当前网络。

## 五、安装软件

### 5.1 安装前准备

安装会替换当前旧版 `YiShuSplit` PowerShell 服务。建议先确认：

- `artifacts` 中已经生成最新发布物。
- 翼枢当前可以正常连接。
- 已保存正在进行的网络工作。
- 已了解安装期间旧分流会被短暂关闭和恢复。

### 5.2 执行安装

在开发目录中使用 PowerShell 7 执行：

```powershell
.\scripts\安装.ps1
```

接受一次管理员权限提示。安装脚本将：

1. 安全停止旧版 `YiShuSplit` 服务，等待其恢复原始路由。
2. 备份旧版配置和资源文件。
3. 删除旧服务注册。
4. 清除旧工具写入的 hosts 托管区块并保留迁移备份。
5. 将新程序安装到 `C:\Program Files\YiShuHelper`。
6. 将运行配置放到 `C:\ProgramData\YiShuHelper`。
7. 注册并启动新的 `YiShuHelper` 自动服务。
8. 为当前用户创建托盘登录启动快捷方式。

安装完成后，后台服务立即运行。托盘程序会在下次登录时自动启动；如需立即使用，可以手动运行：

```powershell
& 'C:\Program Files\YiShuHelper\tray\YiShuHelper.Tray.exe'
```

## 六、托盘菜单

右键单击“翼枢分流助手”托盘图标，可以使用以下功能。

### 6.1 分流状态

菜单顶部显示当前实际状态：

- **已关闭**：用户已经关闭分流，服务不会自动启用。
- **等待翼枢**：用户期望启用，但翼枢进程、隧道或 peer 尚不可用。
- **正在启用**：服务正在执行启用事务。
- **已启用**：目标 `AllowedIPs` 和 Windows 路由均已核验。
- **正在关闭**：服务正在恢复翼枢原始状态。
- **故障**：事务失败，或者系统状态暂时无法确认。

“等待翼枢”不表示故障。可以先打开翼枢并完成连接，后台服务随后会自动应用分流。

### 6.2 启用分流

选择“启用分流”后，后台服务会持久化启用意图：

- 翼枢已经连接时，立即执行启用事务。
- 翼枢尚未连接时，状态变为“等待翼枢”。
- 翼枢后续恢复时，服务自动启用分流。

启用成功前，菜单不会把状态显示为“已启用”。

### 6.3 关闭分流

选择“关闭分流”后，后台服务会：

1. 停止自动启用和重试。
2. 恢复原始 WireGuard `AllowedIPs`。
3. 删除本软件创建的路由。
4. 恢复事务开始前记录的原始路由。
5. 核验结果并删除活动事务快照。

关闭状态会被保存。服务或计算机重启后仍保持关闭，直到用户再次选择“启用分流”。

### 6.4 组件状态

“组件状态”子菜单显示：

- 后台服务。
- 翼枢进程。
- `wg.exe`。
- `misas` 接口。
- WireGuard peer。
- 路由配置。
- 最近一次心跳时间。
- 最近一次错误。

排查问题时，应先查看此处，再查看服务日志。

### 6.5 重新加载配置

只有分流处于“已关闭”状态时，才能重新加载配置。

推荐顺序：

1. 选择“关闭分流”。
2. 编辑配置文件。
3. 选择“重新加载配置”。
4. 确认没有配置错误。
5. 选择“启用分流”。

### 6.6 退出托盘

“退出托盘”只关闭托盘界面，后台服务和当前分流状态保持不变。

## 七、修改路由配置

正式配置文件位于：

```text
C:\ProgramData\YiShuHelper\yishu-split-config.json
```

默认内容如下：

```json
{
  "version": 1,
  "yiShu": {
    "directory": "C:\\Program Files\\YiShu",
    "interface": "misas",
    "processName": "翼枢"
  },
  "routing": {
    "minimumPrefixLength": 8,
    "infrastructurePrefixes": [
      "1.2.3.4/32",
      "172.28.160.193/32"
    ],
    "resourcePrefixes": [
      "172.27.103.0/24",
      "172.28.72.0/24",
      "172.29.16.0/24"
    ]
  }
}
```

字段说明：

- `version`：配置格式版本，当前必须为 `1`。
- `yiShu.directory`：翼枢安装目录。
- `yiShu.interface`：翼枢 WireGuard 接口名称，当前为 `misas`。
- `yiShu.processName`：翼枢进程名称。
- `minimumPrefixLength`：允许应用的最短 IPv4 前缀，防止误配置宽泛路由。
- `infrastructurePrefixes`：翼枢控制面、现有 DNS 等基础设施地址。
- `resourcePrefixes`：需要通过翼枢访问的业务网段。

配置加载时会规范化、排序、去重，并自动去除已被更大网段覆盖的重复前缀。无效 CIDR、空列表、错误版本或过宽路由都会使加载失败，服务不会应用部分配置。

### 7.1 当前基础设施地址

- `1.2.3.4/32`：翼枢控制面地址。
- `172.28.160.193/32`：翼枢写入 `misas` 网卡的 DNS 服务器地址。软件只保证该地址的路由，不负责设置 DNS。

### 7.2 当前资源地址

- `172.27.103.0/24`：包含 `172.27.103.53`。
- `172.28.72.0/24`：翼枢授权资源网段。
- `172.29.16.0/24`：包含 `172.29.16.2` 和 `172.29.16.6`。

## 八、DNS 和 hosts 使用说明

翼枢分流助手不管理域名解析。

本地网关 DNS 可以正常解析的域名无需写入 hosts。用户只需在自己的 hosts profile 工具中保留翼枢专用资源：

```hosts
# 翼枢专用资源
172.27.103.53 snc-cluster.ipsdn.com
172.29.16.6 testnacos.cn
```

上述 profile 只负责把域名解析为 IP：

- `snc-cluster.ipsdn.com` 解析后命中 `172.27.103.0/24`，因此走翼枢。
- `testnacos.cn` 解析后命中 `172.29.16.0/24`，因此走翼枢。

`srdcloud.cn` 系列由本地网关 DNS 解析并走本地网络，不需要本软件或 hosts profile 维护。

## 九、日志和运行数据

运行数据目录：

```text
C:\ProgramData\YiShuHelper
```

主要文件包括：

- `yishu-split-config.json`：正式路由配置。
- `control-state.json`：用户期望启用或关闭的持久状态。
- `transaction-state.json`：活动事务恢复快照，仅在分流已应用时存在。
- `logs\service-日期.log`：后台服务日志。
- `migration-日期时间`：从旧版工具迁移时保存的备份。

日志按日期生成，并自动保留最近十四份。

不要在分流已启用时手工删除 `transaction-state.json`，否则可能失去恢复原始路由所需的信息。

## 十、常见问题

### 10.1 状态一直是“等待翼枢”

依次确认：

1. 翼枢进程是否运行。
2. 是否已在翼枢界面完成连接。
3. `C:\Program Files\YiShu\resources\wg.exe` 是否存在。
4. Windows 中是否出现 `misas` 接口。
5. 托盘“组件状态”中哪个组件异常。

服务会自动重试，不需要反复点击“启用分流”。

### 10.2 状态显示“故障”

先查看“组件状态”中的最近错误，再查看：

```text
C:\ProgramData\YiShuHelper\logs
```

如果故障发生在关闭事务中，不要删除事务快照。恢复翼枢连接后再次选择“关闭分流”，让服务继续完成恢复。

### 10.3 托盘显示后台服务不可用

在管理员 PowerShell 中检查：

```powershell
Get-Service YiShuHelper
```

需要时启动服务：

```powershell
Start-Service YiShuHelper
```

### 10.4 需要紧急停止后台服务

在管理员 PowerShell 中执行：

```powershell
Stop-Service YiShuHelper
```

服务停止前会尝试执行关闭事务并恢复原始路由。停止服务不会把持久化启用意图改成关闭；以后重新启动服务时，如果之前期望启用，它会继续等待或应用分流。

### 10.5 配置修改后无法重新加载

确认当前状态已经是“已关闭”。如果仍然失败，使用 JSON 编辑器检查语法，并确认所有前缀都是合法 IPv4 CIDR。

## 十一、卸载软件

使用 PowerShell 7 执行：

```powershell
cd D:\program\yishu-helper
.\scripts\卸载.ps1
```

卸载脚本会：

1. 停止后台服务并执行路由恢复。
2. 删除服务注册。
3. 退出托盘程序。
4. 删除登录启动快捷方式。
5. 删除 `C:\Program Files\YiShuHelper` 中的程序文件。

默认保留 `C:\ProgramData\YiShuHelper` 中的配置、日志和迁移备份。

如果确认不再需要任何数据，可以执行：

```powershell
.\scripts\卸载.ps1 -RemoveData
```

该参数会永久删除配置、日志、事务记录和迁移备份，使用前应先自行备份。

## 十二、安全注意事项

- 不要同时运行旧版 `YiShuSplit` 服务和新版 `YiShuHelper` 服务。
- 不要在分流已启用时直接修改 WireGuard `AllowedIPs` 或删除受管路由。
- 不要把 `0.0.0.0/0` 等宽泛网段加入资源配置。
- 修改配置前先关闭分流，确保事务边界清楚。
- 出现恢复故障时保留事务快照和日志，不要通过删除状态文件掩盖问题。
- 首次真实安装和网络验证应安排在允许短暂断网的时间进行。
